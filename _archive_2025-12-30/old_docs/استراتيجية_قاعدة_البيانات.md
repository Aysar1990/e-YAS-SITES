# 📊 استراتيجية قاعدة البيانات - Database Migration Guide

## نظرة عامة

يستخدم e-YAS SITES **استراتيجية قاعدة بيانات مزدوجة** تسمح بالتبديل السلس بين:

| قاعدة البيانات | النوع | حالة الاستخدام |
|----------------|-------|----------------|
| **SQLite** | محلية | العمل بدون إنترنت، التطوير، مستخدم واحد |
| **Supabase** | سحابية | العمل الجماعي، عدة مستخدمين، مزامنة فورية |

### متى تستخدم كل منهما؟

| السيناريو | قاعدة البيانات الموصى بها |
|-----------|---------------------------|
| لا يوجد اتصال بالإنترنت | SQLite |
| مستخدم واحد على جهاز واحد | SQLite |
| عدة مستخدمين يتعاونون | Supabase |
| تحديثات فورية مطلوبة | Supabase |
| تطوير / اختبار | SQLite |
| إنتاج (Production) | Supabase |

## إعداد Supabase

### 1. إنشاء مشروع Supabase

1. اذهب إلى [supabase.com](https://supabase.com) وأنشئ مشروعاً جديداً
2. سجل URL المشروع و API Keys من Settings > API

### 2. إنشاء الجداول

نفذ هذا الـ SQL في Supabase SQL Editor:

```sql
-- جدول المواقع (68 عمود)
CREATE TABLE sites (
  -- المفاتيح الأساسية
  id SERIAL PRIMARY KEY,
  site_id VARCHAR(50) NOT NULL,
  phase_name VARCHAR(50) NOT NULL,

  -- معلومات الموقع الأساسية
  site_name VARCHAR(255),

  longitude DECIMAL(11, 8),
  governorate VARCHAR(100),
  district VARCHAR(100),
  city VARCHAR(100),
  site_type VARCHAR(50),
  site_category VARCHAR(50),

  -- الأولوية والحالة
  priority INTEGER DEFAULT 999,
  tssr_overall_status VARCHAR(50) DEFAULT 'Pending',
  comments TEXT,

  -- قسم TI
  ti_assigned_to VARCHAR(100),
  ti_status VARCHAR(50) DEFAULT 'Pending',
  ti_rejection_reason TEXT,
  ti_date DATE,
  ti_notes TEXT,

  -- قسم RF Planning
  rf_plan_assigned_to VARCHAR(100),
  rf_plan_status VARCHAR(50) DEFAULT 'Pending',
  rf_plan_rejection_reason TEXT,
  rf_plan_date DATE,
  rf_plan_notes TEXT,

  -- قسم RF Optimization
  rf_opt_assigned_to VARCHAR(100),
  rf_opt_status VARCHAR(50) DEFAULT 'Pending',
  rf_opt_rejection_reason TEXT,
  rf_opt_date DATE,
  rf_opt_notes TEXT,

  -- قسم Civil
  civil_assigned_to VARCHAR(100),
  civil_status VARCHAR(50) DEFAULT 'Pending',
  civil_rejection_reason TEXT,
  civil_date DATE,
  civil_notes TEXT,

  -- قسم MW
  mw_assigned_to VARCHAR(100),
  mw_status VARCHAR(50) DEFAULT 'Pending',
  mw_rejection_reason TEXT,
  mw_date DATE,
  mw_notes TEXT,

  -- معلومات المقاول
  contractor_name VARCHAR(100),
  contractor_status VARCHAR(50),
  contractor_submission_date DATE,

  -- الطوابع الزمنية
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  last_synced_at TIMESTAMPTZ,

  -- قيد فريد
  UNIQUE(site_id, phase_name)

-- إنشاء الفهارس للأداء
CREATE INDEX idx_sites_phase ON sites(phase_name);
CREATE INDEX idx_sites_status ON sites(tssr_overall_status);
CREATE INDEX idx_sites_contractor ON sites(contractor_name);
CREATE INDEX idx_sites_priority ON sites(priority);
CREATE INDEX idx_sites_governorate ON sites(governorate);

-- جدول المستخدمين
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  email VARCHAR(255),
  role VARCHAR(50) DEFAULT 'contractor',
  full_name VARCHAR(100),
  department VARCHAR(50),
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- جدول الإعدادات
CREATE TABLE settings (
  key VARCHAR(100) PRIMARY KEY,
  value TEXT,
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 3. Row Level Security (RLS)

```sql
-- تفعيل RLS على جدول المواقع
ALTER TABLE sites ENABLE ROW LEVEL SECURITY;

-- سياسة: المدراء يمكنهم فعل كل شيء
CREATE POLICY admin_all ON sites
  FOR ALL
  TO authenticated
  USING (
    (SELECT role FROM users WHERE username = current_user) = 'admin'
  );

-- سياسة: الجميع يمكنهم القراءة
CREATE POLICY read_all ON sites
  FOR SELECT
  TO authenticated
  USING (true);
```

## عملية الترحيل

### من Excel إلى SQLite

1. **افتح التطبيق** في وضع SQLite:
   ```bash
   DATABASE_TYPE=sqlite npm start
   ```

2. **استورد ملف Excel**:
   - اذهب إلى Admin > Import
   - اختر ملف `.xlsm`
   - حدد الـ Worksheets المطلوبة
   - اضغط "Import"

3. **تحقق من البيانات**:
   - افحص Dashboard للتأكد من الأعداد
   - تحقق من عينة من المواقع

### من SQLite إلى Supabase

1. **إعداد credentials** في `.env`:
   ```bash
   DATABASE_TYPE=supabase
   SUPABASE_URL=your_project_url
   SUPABASE_ANON_KEY=your_anon_key
   ```

2. **إعداد server credentials** في `electron/.env.server`:
   ```bash
   SUPABASE_SERVICE_KEY=your_service_key
   ```

3. **شغل script الترحيل**:
   ```bash
   node electron/scripts/migrate-to-supabase.js
   ```

4. **تحقق في Supabase Dashboard**:
   - افحص Tables > sites
   - تأكد من تطابق عدد الصفوف

## قواعد حل التعارضات

عند المزامنة بين قواعد البيانات:

| نوع التعارض | الحل |
|-------------|------|
| نفس الموقع، بيانات مختلفة | الأحدث (`updated_at`) يفوز |
| موقع موجود في قاعدة واحدة فقط | نسخ للقاعدة الأخرى |
| `phase_name` مختلف | تعامل كسجلات منفصلة |
| تعارض في الحالة | السحابي (Supabase) يأخذ الأولوية |

## استكشاف الأخطاء

### "Connection refused" إلى Supabase

**السبب**: مشكلة شبكة أو URL خاطئ
**الحل**:
1. تحقق من `SUPABASE_URL` في `.env`
2. تأكد من اتصال الإنترنت
3. تأكد من نشاط مشروع Supabase

### "Permission denied"

**السبب**: سياسات RLS تحجب الوصول
**الحل**:
1. تحقق من دور المستخدم في جدول users
2. راجع سياسات RLS في Supabase Dashboard
3. استخدم Service Key للعمليات الإدارية

### البيانات لا تتزامن

**السبب**: فشل اتصال WebSocket
**الحل**:
1. تأكد من فتح port 3002
2. تحقق من تفعيل real-time في Supabase
3. افحص console المتصفح للأخطاء

## أفضل الممارسات

1. **دائماً انسخ قبل الترحيل**
   ```bash
   copy data\tssr.db data\tssr_backup.db
   ```

2. **اختبر مع بيانات صغيرة أولاً**
   - صدّر 100 موقع للبيئة الجديدة
   - تحقق من نقل جميع الأعمدة بشكل صحيح

3. **استخدم transactions للعمليات الكبيرة**
   - Supabase يدعم 1000 صف لكل insert
   - قسّم الاستيرادات الكبيرة

4. **راقب حصص Supabase**
   - الطبقة المجانية: 500MB قاعدة بيانات
   - راقب الاستخدام في Dashboard > Settings > Billing
